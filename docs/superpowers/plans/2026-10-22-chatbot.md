# Asistente LumaTek (chatbot): plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Endpoint `POST /api/chat`, compartido por la web y la app móvil, que responde con Claude usando un resumen de los invernaderos de la empresa y acepta una foto opcional, más la página web `/assistant`.

**Architecture:** `GreenhouseSnapshotService` (lógica extraída de `DashboardController`) arma los datos de la empresa. `ChatController` valida, aplica el límite diario y llama a la interfaz `ChatAssistant`, cuya implementación `ClaudeChatAssistant` es la única que usa el SDK. El historial vive en el cliente.

**Tech Stack:** Laravel 13, PHP 8.3+, `tymon/jwt-auth`, `anthropic-ai/sdk` (PHP), Blade + JS sin librerías, PHPUnit con SQLite en memoria.

**Spec:** `docs/superpowers/specs/2026-10-22-chatbot-design.md`

## Global Constraints

- Reglas de `AGENTS.md`: no modificar `.env`, no hacer commit, push ni merge sin autorización expresa del usuario, no ejecutar operaciones destructivas de BD y mantener el aislamiento entre empresas.
- Todo el texto visible para el usuario va en español.
- Modelo por defecto `claude-opus-5-5`; `CHAT_DAILY_LIMIT=50`; timeout 30 s; `max_tokens` 2048; esfuerzo `low`.
- Historial: de 1 a 20 mensajes; `content` de 1 a 4000 caracteres; los roles se alternan; el primero y el último son `user`.
- Imagen: jpeg/png/webp, máximo 5 MB (`max:5120`), nunca se guarda en disco.
- Clave de caché: `chat:{company_id}:{Y-m-d}`, que expira al final del día; solo se incrementa con una respuesta exitosa.
- Códigos: `chat_limit_reached` (429) y `assistant_unavailable` (503).
- Las pruebas nunca llaman a la API real.
- Las pruebas usan `Tests\Concerns\UsesInMemoryDatabase` y se ejecutan con `php artisan test`.

## Review Focus

1. Un historial enviado como JSON válido pero con una forma inesperada (objeto en lugar de arreglo, `content` numérico o con roles desconocidos) → debe dar 422, no 500. Prueba en la Tarea 3.
2. La petición que pasa del límite (por ejemplo, la número 51) → 429 sin llamar al asistente, y `remaining_today` nunca negativo. Prueba en la Tarea 3.
3. La extracción del dashboard → `GET /api/dashboard` debe devolver exactamente el mismo JSON. Prueba en la Tarea 1, escrita antes del refactor.
4. Una respuesta del modelo con `<script>` o HTML → la web debe mostrarla como texto. Verificación manual en la Tarea 5.
5. Datos de otra empresa o recursos con `plan_restricted` → nunca aparecen en el resumen. Prueba en la Tarea 2.
